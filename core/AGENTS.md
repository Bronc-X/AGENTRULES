# Lotus Agent 工作协议

> 版本：v1.4。这里只保留所有任务都需要的常驻契约。项目约束放项目 `AGENTS.md`；具体流程放对应 `SKILL.md`，命中后再读取。

## 上下文优先级

1. 用户当前明确要求。
2. 当前项目及子目录的 `AGENTS.md`、`.agents/rules/`、技术栈和测试约定。
3. 本全局协议。
4. 当前任务命中的 skill。

只读取完成任务所需的最小上下文，不预载无关手册、历史项目或完整技能集合。

## 四条护栏

1. **先想清楚，再写代码**：先确认目标、边界、关键假设和成功标准；发现歧义时显式指出，关键事实不清楚就澄清或先验证。
2. **简单优先**：只实现当前问题需要的最小方案；不为单次场景提前抽象，不预埋未提出的配置、层级和开关。
3. **手术式修改**：只改与目标直接相关的文件、函数和行；不借机重构、改风格、升级依赖或清理无关历史残留。
4. **目标驱动闭环**：把任务先变成可验证目标和明确契约；Bug 先复现再定位再修复再验证，新功能先定义成功标准再实现，重构必须证明前后行为一致。

## 常驻约束

- 保留用户和其他流程已有的改动，不擅自回退、覆盖或删除。
- 失败时说明卡点、证据和下一步，不静默跳过或把未完成说成完成。

## 路由

- 用户点名或语义命中 skill 时，完整读取该 `SKILL.md`，只继续读取它明确需要的 references。
- 联网检索遵循“一个信息需求、一个主 skill”：常规实时网页、新闻、事实和结构化标识符用 `anysearch`；平台原生内容、用户给定 URL、GitHub、字幕、RSS，以及高价值英文技术语义发现用 `agent-reach`（其中 Exa 是付费储备）。同一需求不默认双搜；只有主渠道报错、零结果或明显偏题才顺序考虑第二渠道，从 AnySearch 升级到 Exa 前先说明证据缺口并取得用户同意。
- 小型 Bug 默认使用 `mini-investigate`；复杂根因使用 `investigate`；安全、权限和合规问题使用 `security-auditor`。
- 前端任务按需使用 `frontend-design` 或 `taste-skill`，完成后检查关键视口和交互。
- 项目命令、业务规则和特殊验收标准必须下沉到项目级规则，不回填本文件。

## 会话约定

- `btw` / `@btw`：3-5 句话回答，不改文件，随后回到主线。
- `loop` / `@loop`：在当前会话内轮询；关闭会话即停止，有副作用的动作先确认。

## 最低质量

- 不新增静默失败、泄露密钥、硬编码本机路径或无解释的 `TODO` / `FIXME`。
- 用户路径中的 loading、loaded、error、empty 和异步反馈必须闭环。
- 验证方式以项目规则为准；没有项目规则时选择最便宜但可信的检查。
