# 上传、发布与分发

## 两阶段模型

### 阶段 A：制作发布候选

可以根据用户早期意图完成：

- 最终文件和公开元数据。
- 平台规格检查。
- 目标平台与账号解析。
- 发布预览和不可变 release manifest。

此阶段不执行外部写入。即使用户说“一条龙”“直接发”“做好就发”，也先完成候选并停在最终确认前。

### 阶段 B：绑定确认后写入

确认必须明确绑定：

- 哪些 artifact 与 SHA-256。
- 哪个平台。
- 哪个账号/节目/空间。
- 是草稿上传还是公开发布。
- 预览时间和用户确认原文。

任何一项改变，原确认失效，生成新候选并重新确认。

## 权限粒度

- `DRAFT_UPLOAD` 只允许上传为不可见草稿。
- `PUBLIC_RELEASE` 只允许指定候选在指定平台和账号公开。
- 某个平台的批准不扩展到其他平台。
- 文案发布批准不包含音频上传；封面批准不包含正文修改。
- 上传或发布失败时停止并报告，不猜账号、不换平台补发、不无限重试。

## 发布前检查

- 平台登录态和目标账号可见且与确认一致。
- 文件、标题、简介、作者、节目名、封面和标签均为已预览版本。
- 公开资产中不含 `UNKNOWN`、`UNRESOLVED`、内部路径、个人信息、占位词或内部审阅标记。
- 媒体规格、版权、事实、完整听审/视觉 QA 均通过。
- release manifest 与最新母库、分支 QA、授权事件哈希一致。

## 发布后状态

分别记录：

1. `UPLOADED`：平台收到文件。
2. `PUBLISHED`：平台标记公开。
3. `DIRECT_URL_REACHABLE`：直接链接可访问。
4. `INDEXED`：平台搜索可以找到。
5. `REGION_VISIBLE`：目标地区可见。

搜索索引延迟不等于发布失败；平台已发布也不等于所有地区已可见。

公开后返回平台、账号、内容版本、直接链接、发布时间和验证状态。不要在未验证时声称“已全网可见”。
