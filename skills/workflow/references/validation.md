# 工作流验证

## 最小验证组合

1. **黄金回放**：用真实成功样本证明新工作流仍能得到被接受的结果。
2. **负向案例**：重放至少一个已知弯路或越权场景，证明门禁能提前阻断。
3. **边界案例**：验证一个规模、输入缺失、权限不足或条件分支边界。
4. **独立前向测试**：让未参与设计的执行者只读取工作流和隔离的原始输入包，从头完成一次任务。

评测提示不得提前透露预期路径、已有答案或已知缺陷；把验收标准与执行请求分开，使用独立工作目录。大型媒体可分层验证，但必须声明预算、抽样层级和哪些产物完成了全量验证；抽样不能冒充全量前向测试。

## 判定

- `DRAFT`：结构存在，但没有真实通过证据。
- `LOCALLY_VALIDATED`：真实项目回放通过，尚无独立前向测试或覆盖范围有限。
- `VERIFIED`：黄金、负向、边界和独立前向测试均通过；审阅后的 QA 命令以 `--execute` 运行并返回 0，所有记录与当前工作流定义哈希一致。
- 任一受保护行为回归：立即降级到 `DRAFT` 或 `LOCALLY_VALIDATED`，不得沿用“已验证”标签。

行为验证与优化声明相互独立：`VERIFIED + UNASSESSED` 是合法状态。

当前声明组合固定为：`DRAFT`、`LOCALLY_VALIDATED` 和 `DEPRECATED` 只能配 `UNASSESSED`；`VERIFIED` 可以配 `UNASSESSED`，也可以在对应优化证据通过后配两个受限声明之一。较低状态可以保存候选数据或消融计划，但不能把它们展示成当前最短性结论。

## 最短性审查

对每个主路径步骤做一次删除实验或反事实说明：

- 删除后黄金结果是否仍相同？
- 删除后负向案例是否仍被拦截？
- 删除后是否仍可追溯和恢复？
- 删除后是否扩大权限或增加人工猜测？

四项全部满足才允许删除。合并、自动化或并行也要用相同标准验证。每个保留的主路径步骤绑定一个 `ABLATION` 案例后，只能声明 `IRREDUCIBLE_WITHIN_VALIDATED_SCOPE`。

若要声明 `SHORTEST_AMONG_TESTED_CANDIDATES`，必须：

- 至少有两条实际测试、都满足硬约束的候选路径。
- 先声明比较指标与方向，再记录每条候选的指标和证据。
- 每条候选用步骤、分支、门禁和关键配置计算 canonical JSON SHA-256；至少有两个不同 fingerprint，不能只换候选 ID 或自报不同指标。
- 每条候选的首个证据文件必须把候选 ID、path fingerprint、硬约束结果和指标重新绑定到同一份测试收据。
- 入选路径在这些候选中取得最优指标。
- 结论同时展示候选集合、适用范围和未验证条件。

## QA 命令

工作流包使用：

```powershell
python scripts/run_validation_commands.py <workflow-pack-path>            # 只预览计划
python scripts/run_validation_commands.py <workflow-pack-path> --execute  # 审阅后执行
python scripts/qa_workflow_pack.py <workflow-pack-path> --strict
```

需要验证优化声明时使用：

```powershell
python scripts/qa_workflow_pack.py <workflow-pack-path> --require-optimization
```

结构检查通过不等于行为通过。严格模式还要求：

- 不存在 `__UNRESOLVED__`、`[TODO: ...]` 或模板占位符；业务本身合法使用 `PENDING` 状态不应被误判。
- 成功证据、黄金样本、负向案例、范围和停止条件存在，包内证据文件非空且 SHA-256 匹配。
- 每个 gate 和条件分支都有通过案例覆盖；外部写入与不可逆步骤有对应授权或安全门禁。
- 独立前向测试记录执行者、输入摘要、时间和精确工作流定义哈希。
- QA 命令使用 argv、无 shell 执行；runner 记录退出码、输出哈希、时间、自身版本与脚本哈希，以及工作流定义哈希。
- 定义文件在验证后发生任何变化，旧命令证据和前向证据立即失效。

最终报告应给出命令、退出码、通过/失败计数和未验证条件，而不是只写“测试通过”。

本地 JSON 记录不是可信执行证明：任何拥有包写权限的人都可能伪造文件。严格 QA 证明的是结构、内容、哈希和绑定关系一致；如果审计场景要求防篡改来源，必须由包外可信 CI、受限执行环境或签名审计系统出具回执。runner 的 `--execute` 仍是未沙箱化的本地进程，只能运行人工确认过的可信命令。
