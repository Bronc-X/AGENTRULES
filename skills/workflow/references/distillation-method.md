# 路径蒸馏方法

## 1. 建立成功契约

只用最终被接受的结果定义成功，不用最初猜测代替。至少记录：

- 用户可观察结果与验收标准。
- 范围内、范围外以及明确停止点。
- 最终产物、版本、哈希或其他稳定标识。
- 通过的测试、人工确认和外部系统状态。
- 仍未完成但不阻断本阶段的事项。

如果“跑通”只代表技术命令成功，而用户结果、内容质量或外部状态尚未成立，必须拆开描述，不能统一写成完成。至少区分：

- `TECHNICAL_PASS`：命令、构建或文件校验通过。
- `USER_ACCEPTED`：用户可观察结果已经验收。
- `EXTERNAL_VERIFIED`：外部平台或生产状态已独立验证。

## 2. 建权威版本图，再重建轨迹

大型项目先限定扫描预算和忽略规则。优先读取状态文件、最终候选清单、提交、哈希和验收事件；默认忽略缓存、临时目录、旧压缩包、重复导出和已声明弃用的版本。若存在多个“final”，先建立版本权威图：候选 ID、父版本、时间、哈希、状态和被哪个验收事件接受。

扫描预算耗尽仍无法确定权威版本时，包状态保持 `DRAFT`，并把无法确认的事实标成 `UNVERIFIED`；不要靠文件名或修改时间猜最终结果。

证据优先级建议：

1. 最终产物与机器状态。
2. 测试、日志、命令输出和审计事件。
3. 文件、提交和任务时间线。
4. 用户纠正与验收原话。
5. 执行者的事后说明。

对每个动作记录：

```text
step_id / at / actor / input / action / output / duration
dependency / user_touchpoint / failure / retry / evidence
```

无法找到证据时标 `UNVERIFIED`，不要补写一条看似合理的路径。

## 3. 分类矩阵

| 分类 | 判定 | 固化方式 |
|---|---|---|
| `INVARIANT` | 删除后会破坏结果、权限、安全或可复现性 | 留在主路径或强制门禁 |
| `DEFAULT` | 对这一类项目通常更优，但允许有证据地覆盖 | 写成默认值和覆盖条件 |
| `CONDITIONAL` | 只有明确触发条件时需要 | 移到分支并写 `when` |
| `LOCAL_DETAIL` | 只属于这次客户、品牌、路径或账号 | 留在项目配置，不进入通用 Skill |
| `DETOUR` | 没有增加最终价值，或由错误假设、遗漏门禁导致 | 从主路径删除，写入弯路与防回归 |

再问六个压缩问题：

1. 这一步能删吗？
2. 能被更早、更便宜的检查替代吗？
3. 能与同一决策点合并确认吗？
4. 能自动化而不扩大权限吗？
5. 能与其他步骤安全并行吗？
6. 输入未变时能按哈希幂等复用吗？

## 4. 弯路转门禁

每个弯路写成：

```text
症状 → 根因 → 浪费动作 → 最早信号 → 新门禁 → 验证方法
```

只保存能改变未来决策的教训。单次偶发、工具噪音和已经由上层规则覆盖的内容不应无限累积成新规则。

## 5. 推导最短安全路径

依次执行：

1. 删除所有 `DETOUR`。
2. 把 `LOCAL_DETAIL` 移进项目配置或 profile。
3. 把低频 `CONDITIONAL` 移出主路径。
4. 把格式、存在性和静态资源等稳定、纯读取检查前移；配额、会话和授权等可变状态必须在副作用发生前再次验证。
5. 把同一时刻可以决定的内容合并成一次用户确认。
6. 在输入不可变、输出不冲突时并行。
7. 只有昂贵、确定、可重放的步骤才增加缓存；缓存键必须覆盖语义输入、环境、工具/模型版本和权限域，任一变化都 cache miss。
8. 保留质量、权限、安全、发布和不可逆操作的独立门禁。

删除任一步后，都要重跑黄金样本和负向案例。若黄金结果变化、负向案例漏过、证据链断裂或权限扩大，该步骤不可删除。

## 6. 双层工作流

用户层只显示有意义的决策或可观察状态，通常不超过 7 个节点，不为了凑数量增加动作。执行层保留：

- 精确输入输出。
- 状态与可进入条件。
- 人工决策点。
- 条件分支。
- 失败反馈、恢复和停止条件。
- 验收证据与产物哈希。

用户层短，不等于内部省略门禁。

## 7. “最优”的适用范围

把结论限定到已经验证的输入类型、环境、规模和风险等级。

- `VERIFIED`：工作流在该范围内可复现，不代表路径最短。
- `IRREDUCIBLE_WITHIN_VALIDATED_SCOPE`：每个主路径步骤都有通过的消融证据，只能说明当前路径逐步不可删。
- `SHORTEST_AMONG_TESTED_CANDIDATES`：至少两条满足硬约束的候选路径已按用户声明的指标比较，入选路径在这些候选中最短。

不要把局部不可约说成全局最短，也不要声称数学上的全局最优。
